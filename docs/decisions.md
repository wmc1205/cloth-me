# 결정 기록

> "왜 이렇게 정했는지"를 남기는 문서다. 필요할 때만 읽는다. 새 결정은 아래에 추가한다.

## 2026-10-23
- **백엔드는 Next.js로 통일** (Spring Boot 미사용): Vercel 배포와 가장 잘 맞고, 화면+API를 한 프로젝트에서 관리하기 위해.
- **쇼핑 상품은 네이버 쇼핑 검색 API + 링크 붙여넣기 위시리스트**
  - 지그재그/에이블리는 개발자용 공개 상품 API를 찾지 못함. 스크래핑은 약관/차단/유지보수 문제로 하지 않음.
  - AI는 검색어만 만들고, 실제 상품 정보는 API 결과만 사용.
- **웹(모바일 우선) → PWA → (선택) Expo 앱 순서**
  - 핵심 가치는 서버의 AI 로직이라 웹에서 먼저 검증. 앱은 같은 서버를 호출.
  - 핵심 기능은 Route Handler(API)로 만들고, 서버 액션에는 핵심 로직을 두지 않음(앱에서 호출 불가).
- **레퍼런스**: 서비스 — Acloset, Cladwell, Fits / 오픈소스 — Lime, Stylesync, OutfitAI Studio
- **토큰 절약을 위한 파일 역할 분리**: CLAUDE.md는 짧게(항상 로드), 상세 규칙은 스킬(필요할 때 로드), 배경 설명은 docs/.
- **Spring Boot + TS 분리안은 검토 후 보류, Next.js + Vercel 유지**: 목표가 "빠른 출시 + 하네스 엔지니어링 + 코드 검증을 한 번에"라서 프로젝트 1개·서버리스 배포로 가볍게 간다. (분리안은 프로젝트 2개, 서버 운영, CORS/인증 직접 처리가 추가로 필요)
- **확신 없는 API는 추측 금지**: `// [문서확인] 이 부분은 관련 문서를 확인해야 합니다: ...` 주석을 남기고, PR 전에 grep으로 남은 항목을 점검한다.
- **프로젝트 이름은 '옷스스메'** (옷 + おすすめ). 폴더/npm 패키지 이름은 영문 소문자 슬러그를 따로 정한다(미정).
- **에이전트는 A안**: `planner`, `backend`, `reviewer` 유지 + `frontend` 추가. db/config는 에이전트로 쪼개지 않고 스킬(`db-migration` 등)로 관리한다. (기능 하나가 여러 레이어를 지나가고, 에이전트마다 컨텍스트를 새로 읽는 토큰 비용이 늘기 때문)
- **DB는 Supabase + `supabase-js` + 생성 타입 + SQL 마이그레이션, ORM 없음**: 사용자 세션으로 접근하면 RLS가 자동 적용되어 "본인 데이터만" 규칙을 지키기 쉽다. 복잡한 조인/트랜잭션이 늘면 Drizzle 추가를 재검토한다.

## 2026-10-30
- **쇼핑 연동을 네이버 쇼핑 API에서 "검색 바로가기 링크"로 교체**: 네이버 쇼핑 검색 API(`/v1/search/shop.json`)가 2026-07-31에 종료됐고 NAVER API HUB로 이관되지 않았다(HUB에는 쇼핑인사이트=검색량 통계만 있어 상품·가격을 줄 수 없음). 개발자센터의 신규 키 발급도 중단되어 새 Client ID/Secret을 받을 수 없다.
  - AI는 검색어만 만들고, 코드가 네이버쇼핑·구글 쇼핑 검색 페이지 링크를 만든다(`src/lib/shopping/search-links.ts`). 스크래핑·키·제휴 신청이 필요 없다.
  - 대가로 상품 이미지·가격은 앱에서 보여주지 못한다. 필요해지면 쿠팡 파트너스 등 공식 API를 별도 조사한다(승인·제휴 고지 필요, 미확인).
  - 근거는 2차 자료(waffleboard 가이드, GitHub PR 등)가 개발자센터 공지 32564·32530을 인용한 것이다. 공식 공지 페이지는 직접 확인하지 못했다.
  - NAVER API HUB의 블로그/뉴스 검색·쇼핑인사이트는 계속 제공되므로, 패션 동향 수집(`TREND_CONTEXT`)에 쓸 수 있다(NCP 계정 필요).
