# 소스 분석 먼저 (plan mode)

## 언제 쓰나
- 폴더/패키지 단위로 훑어보거나 수정할 때
- 리팩터링, 컨벤션 일괄 적용, 3개 이상 파일을 건드리는 변경

## 절차
1. **plan mode로 전환한다.** (읽기 전용이라 분석 중 실수로 수정하지 않는다)
   - 세션 중: `Shift+Tab`으로 모드 전환 / 새로 시작할 때: `claude --permission-mode plan`
2. **범위를 정한다.** 대상 폴더를 사용자에게 확인한다. 모호하면 질문한다.
3. **토큰을 아끼며 읽는다.**
   - `Glob`으로 파일 목록 → `Grep`으로 필요한 패턴 → 필요한 파일만 `Read` (큰 파일은 `offset/limit`)
   - 폴더 전체를 통째로 읽지 않는다.
   - 탐색 범위가 넓으면 `Explore` 에이전트에 맡기고 **결론만** 받는다.
4. **분석 결과를 계획서로 정리한다.** (길게 쓰지 않는다)
   - 현재 구조 한 단락
   - 문제점 목록: `파일:줄` + 어떤 컨벤션/규칙 위반인지
   - 수정 계획: 파일별 변경 내용, 순서, 위험한 부분
   - 확인 방법: 테스트 명령 또는 화면 경로
5. **사용자 승인을 받은 뒤** plan mode를 끝내고 구현한다. 승인 전에는 파일을 수정하지 않는다.
6. 구현은 **폴더/기능 단위로 나눠서** 커밋한다. 한 번에 크게 바꾸지 않는다.

## 참고
- 이 절차는 지시문일 뿐 자동으로 강제되지 않는다. 확실히 하려면 위 `--permission-mode plan`으로 시작한다.
- 컨벤션 기준은 `code-convention` 스킬을 따른다.
