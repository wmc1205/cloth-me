# 쇼핑 상품 추천

## 핵심 원칙
**AI는 "무엇이 필요한지(검색어)"만 말하고, 실제 상품은 API가 가져온다.**
AI가 상품명/가격/링크를 만들면 가짜 정보가 섞이므로 절대 금지.

## 흐름
1. 코디 추천 결과의 `shoppingHints[].query` (예: "베이지 와이드 슬랙스")를 받는다.
2. 서버가 캐시를 먼저 확인한다. (검색어+정렬 기준 키, 약 24시간)
3. 캐시가 없으면 네이버 쇼핑 검색 API를 호출한다.
4. 응답을 정리(HTML 태그 제거, 필요한 필드만 추출)하고 Zod로 검증한다.
5. 결과를 캐시에 저장하고 화면에 반환한다.

(선택) 후보가 많을 때 AI에게 "코디와 가장 어울리는 3개"를 고르게 한다. 이때도 **API 결과에 있는 productId 안에서만** 고르게 한다.

## 네이버 쇼핑 검색 API
- 엔드포인트와 한도는 **구현 전에 공식 문서에서 확인**한다. (네이버 API 플랫폼이 NAVER API HUB로 정리되는 중이라 호출 한도 정책이 바뀔 수 있음)
- 인증: 요청 헤더에 Client ID / Secret을 넣는다. (환경변수 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, **서버에서만 사용**)
- 주요 요청 값: `query`(검색어), `display`(개수, 기본 10~20 권장), `sort`(정확도/가격순 등)
- 응답에서 쓸 필드: 상품명, 링크, 이미지, 최저가, 판매처(mall), 브랜드, 상품 ID
- 상품명에 `<b>` 같은 HTML 태그가 섞여 있으니 **제거**한다.

## 정리된 상품 형식 (Zod)
```ts
{
  productId: string,
  title: string,      // 태그 제거 후
  link: string,       // 판매처 링크 (https만 허용)
  image: string,
  price: number,      // 최저가
  mallName: string,
  brand?: string
}
```

## 규칙
1. 검색어는 AI가 만들되, 길이(예: 40자)와 금지어를 서버에서 검사한다.
2. 호출 한도 초과(429)나 타임아웃이면 **캐시된 이전 결과** 또는 "잠시 후 다시 시도" 메시지를 반환한다. 앱이 죽으면 안 된다.
3. 링크는 `https://`만 허용하고, 클릭하면 판매처로 이동(새 탭)하게 한다.
4. 화면에 "상품 정보는 참고용이며 가격/재고는 판매처에서 확인하세요" 문구를 넣는다.
5. 제휴 링크(쿠팡 파트너스 등)를 쓰게 되면 해당 서비스가 요구하는 고지 문구를 반드시 표시한다. (현재는 제휴 미사용)

## 테스트
- 네이버 API 응답은 **목(mock) 데이터**로 단위 테스트한다. (실제 API는 호출 한도를 쓰므로 CI에서 호출하지 않는다)
- 테스트 항목: 태그 제거, 429 처리, 캐시 적중, 잘못된 응답 형식(Zod 실패)
